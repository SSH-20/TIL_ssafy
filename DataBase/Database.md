 # 데이터 베이스
 데이터란? 
 > 저장이나 처리에 효율적인 형태로 변환된 정보

### **데이터베이스 역할**
> 데이터를 저장(구조적 저장)하고 조작

### **관계형 데이터베이스**
> 데이터 간에 관계가 있는 데이터 항목들의 모음

### **관계**
> 여러 테이블 간의 (논리적) 연결

고객 데이터 간 비교를 위해서는 어떤 값을 활용해야 할까?  

- 각 데이터에 고유한 식별 값을 부여하기 (기본키, PK)

누가 어떤 주문을 했는지 어떻게 식별할 수 있을까?
- 주문 정보에 고객의 고유한 식별 값을 저장하기 (외래키, FK)


1. Table (Relation)
2. Field(Column, Attribute)
    - 각 필드에는 고유한 데이터 형식(타입)이 지정됨
3. Record (Row, Tuple)
    - 각 레코드에는 구체적인 데이터 값이 저장됨
4. Database와 Schema
    - DBMS에 따라 계층과 의미가 다름
5. Primary Key (기본 키, PK)
    - 각 레코드의 고유한 값
    - 관계형 데이터베이스에서 레코드의 식별자로 활용
6. Foreign Key(외래키, FK)
    - 테이블의 필드 중 다른 테이블 코드를 식별할 수 있는 키
    - 다른 테이블의 기본 키 또는 Unique 키를 참조하며, 컬럼이 NULL을 허용하면 NULL도 가능
    - 각 레코드에서 서로 다른 테이블 간으 ㅣ관계를 만드는 데 사용

## ***RDBMS***

## ***Database Modeling***
- 데이터베이스 시스템을 구축하기 위함 과정으로 데이터 구조, 관계, 특성을 결정하는 작업
- 효율성, 일관성, 무결성을 보장하기 위해 진행하는 중요한 단계

### **무결성 제약조건**
> 데이터베이스의 데이터 일관성을 유지하고 부적절한 데이터의 삽입, 수정, 삭제를 방지하여 데이터의 신뢰성을 보장하는 조건

### 1. 개체 무결성 (Entity Integrity)
- 기본 키의 값이 중복되지 않고, NULL값이 허용되지 않는 것을 보장하는 제약 조건
    - 각 레코드는 유일한 식별자를 가져야 한다.
    - 기본 키는 NULL 값을 가질 수 없다.

### 2. 참조 무결성 (Referential Integrity)
- 외래 키와 참조 키 간의 관계를 유지하고, 무효한 참조를 방지하는 제약 조건
    - 외래 키 값은 참조하는 테이블의 기본 키 또는 Unique 키와 일치해야 하며, 해당 컬럼이 NULL을 허용하면 NULL 도 가능하다.

### 3. 도메인 무결성 (Domain Integrity)
- 각 속성의 값이 정의된 도메인에 속하는 것을 보장하는 제약 조건
    - 도메인은 속성이 가질 수 있는 값의 범위, 형식, 제약 조건 등을 정의해야 한다.
    - 속성 값이 도메인에 속하지 않는 경우에는 삽입 또는 수정을 제한하거나 오류를 발생시킨다.

### 4. 그 외 무결성 제약 조건
- UNIQUE 제약
    - 특정 컬럼의 값이 테이블 내에서 중복되지 않도록 제한

- NOT NULL 제약
    - 특정 컬럼이 NULL 값을 가질 수 없도록 강제

- CHECK 제약과 비즈니스 규칙
    - 도메인과 비즈니스 로직에 따라 추가 무결성 규칙을 정의함

### **데이터베이스 모델링 진행**
> 옥구사항 수집 및 분석 > 개념적 설계> 물리적 설계

### 1. 요구사항 수집 및 분석
- 어떤 종류의 데이터를 정리하는 정보 수집하고 어떤 작업을 수행하야 하는지 파악하는 안계
    - 개체 (Entity)
        - 업무에서 독립적으로 식별하고 관리할 대상

    - 속성 (Attribute)
        - 개체의 특성을 나타내는 데이터 항목

    - 관계 (Relationship)
        - 객체 사이의 논리적인 연관성을 의미하는 것


### 2. 개념적 설계
- 요구사항을 기반으로 데이터베이스의 개념적 모델을 설계
- 개체와 관계를 식별하고, 개체 간의 관계를 정의하여 관계-다이어그램 을 작성

### 3. 논리적 설계
- 개념적 설계를 기반으로 데이터베이스의 논리적 구조를 설계
- 테이블, 칼럼(속성), 제약조건 등과 같은 구체적인 데이터베이스 개체를 정의
- 정규화를 수행하여 데이터의 중복을 최소화하고 일관성을 유지

### 4. 물리적 설계
- 논리적 설계를 기반으로 데이터베이스를 실제 저장 및 운영할 수 있는 형태로 _x000B_ 변환하는 단계
- 테이블의 인덱스, 파티션, 클러스터링 등 물리적인 구조와 접근 방식을 결정
- 보안, 백업 및 복구, 성능 최적화 등을 고려하여 데이터베이스를 설정


## 정규화
- 불필요한 데이터를 제거하여 중복을 최소화 하기 위해
- 각 종 이상 현상을 방지하기 위해
- 데이터베이스 구조를 변경할 때 다시 구조화 해야 하는 영역을 최소화

## 이상 현상 (Anomaly)
- 데이터베이스를 잘못 설계 했을 때 발생할 수 있는 불필요한 데이터 중복으로 인한 부작용

1. 삽입 이상
    - 새로운 데이터를 삽입하기 위한 불필요한 데이터도 함께 삽입해야 하는 문제
2. 갱신 이상
    - 중복된 데이터 중 일부만 변경하여 데이터가 불일치되는 문제
3. 삭제 이상
    - 데이터를 삭제하는 경우, 반드시 있엉 하는 데이터까지 같이 삭제되는 문제

## **정규화 종류 및 규칙**

### **제 1 정규화**
- 각 속성이 원자적이어야 함
    - 각 속성(컬럼)이 원자값만을 가져야 함
- 2 개를 초과하는 값을 저장할 수 없음
- 해결을 위해 column을 추가하는 경우, 불필요한 NULL 값을 갖게 됨
- 동일 데이터를 여러 row로 나누어서 저장하는 경우, 기본 키가 중복 됨

> 테이블을 분리하자!


### **제 2 정규화**
- 제 1 정규형을 만족하면서, 부분 함수 종속이 없어야 함
    - 즉, 테이블의 모든 컬럼이 기본키에 대해 완전하게 종속되어야 함
    - 기본 키의 일부만으로 결정될 수 있는 속성 제거( 새로운 테이블로 분리 )

### **제 3 정규화**
- 제 2 정규형을 만족하고, 비주요 속성이 후보 키에 이행적으로 함수 종속되지 않아야 함
- 이행적 함수 종속이란
    - A -> B, B -> C가 성립할 때, A -> C가 성립하는 것
    - 비주요 속성이 다른 비주요 속성에 종속되는 경우를 의미함

- 즉, 기본키(PK)가 아닌 속성 간의 종속성을 제거해야 함.
- 비 기본 키 컬럼이 다른 비 기본 키 컬럼을 결정하면 안 됨

### **후보키**
- 후보키란?
    - 테이블에서 각 행을 유일하게 식별할 수 있는 속성(또는 속성의 조합) 중, 최소성을 만족하는 키를 의미
- 후보키의 조건
    - 유일성(Unique) : 테이블의 각 행을 고유하게 식별할 수 있어야 함
    - 최소성(Minimality) : 불필요한 속성을 포함하지 않는 최소한의 속성 조합이어야 함

### **BCNF**    
- 모든 비자명 함수 종속 X -> Y에서 X가 슈퍼키여야함
    - 3NF보다 엄격하며, 3NF에서도 일부 이상현상이 남을 수 있음
    - 후보 키가 아닌 결정자가 존재하면 BCNF를 위반함

- 모든 결정자가 슈퍼키가 되도록 분해하는 정규형
    - 비자명 함수 종속의 결정자는 반드시 슈퍼키여야 함

## SQL
### **수행 목적에 따른 SQL Statements 4가지 유형**
- DDL
    - 데이터의 기본 구조 및 형식 변경
    - CREATE, DROP, ALTER, TRUNCATE

- DQL
    - 데이터 검색
    - SELECT

- DML
    - 데이터 조작 (추가, 수정, 삭제)
    - INSERT, UPDATE, DELETE

- DCL / TCL
    - 권한 제어 / 트랜잭션 제어
    - GRANT, REVOKE
    - COMMIT, ROLLBACK
